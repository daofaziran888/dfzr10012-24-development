# 实时流数据处理中心

面向实时数据处理团队的流式计算与管理中心。覆盖流数据源接入、流处理算子编排、窗口计算配置、状态后端管理、检查点恢复、反压监控、延迟追踪与流作业运维的完整实时计算链路。

这是一个前后端分离的管理平台：前端 React + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 空闲事件流水位推进与窗口收口

`watermark-progress` 在只读的 WATE 水位线配置之上，补齐空闲超时后的可确认水位记录，
推进记录里始终保留**可确认水位、迟到事件缓冲、触发窗口**三块可核对结果，并带**版本标识**：

- 阅读配置的时间字段、空闲超时（如 `30s`）与延迟容忍（如 `10s`），按时间字段校验事件时间；
- 只有空闲周期内无新事件且达到空闲超时，心跳才推进可确认水位；无数据或未超时时保留原结果；
- 事件时间早于可确认水位的迟到事件只进缓冲，重复迟到事件去重，不重复生成窗口触发；
- 同一配置的并发更新用「按配置加锁 + `expected_version` 乐观版本号」控制，只接受一个版本；
- 窗口收口只能依据当前这份可核对记录：版本不一致判冲突，窗口结束时间未越过水位时拒绝提前关闭；
- 失败项保留失败原因并可重试；跨数据链路同步同一份记录，消费侧提交并维护版本标识。

主要接口（前缀 `/api/watermark-progress`）：

| 接口 | 作用 |
| --- | --- |
| `POST /{配置编号}/events` | 写入事件，校验时间字段后归类，支持 `expected_version`、`processed_at` |
| `POST /{配置编号}/tick` | 空闲心跳，达到空闲超时才推进水位 |
| `POST /{配置编号}/windows` | 登记待收口窗口 |
| `POST /{配置编号}/windows/{窗口编号}/close` | 依据版本与水位执行窗口收口 |
| `POST /{配置编号}/retry` | 重试失败项并刷新失败原因 |
| `POST /{配置编号}/sync` | 跨链路同步同一份记录，消费侧维护版本标识 |

验收样例（WATE-0002：时间字段 `ts`、空闲超时 `30s`、延迟容忍 `10s`）：
10:00 到达事件后水位为 09:59:50；10:00 至 10:00:35 无事件，10:00:35 心跳空闲 35s ≥ 30s，
水位推进至 09:59:55；随后 `late-event-24`（事件时间 09:59:00）进入迟到事件缓冲且不回退水位。
脚本验收：`cd backend && .venv/bin/python tests/test_watermark_progress.py`。
